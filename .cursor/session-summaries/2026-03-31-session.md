## 2026-03-31 (later) — Gradle cache / `metadata.bin`
- `flutter run` on Android failed with `Could not read workspace metadata` under `~\.gradle\caches\8.14\transforms\...\metadata.bin` while resolving `dev.flutter.flutter-plugin-loader`.
- Mitigation documented in `CLAUDE.md`: stop Gradle daemons (`gradlew --stop` with `JAVA_HOME`), remove locked `java.exe` if needed, delete user cache `8.14` (or `transforms` only), clear `frontend/android/.gradle`, `flutter clean`, rebuild.
- **Clarification:** `flutter clean` does not touch `%USERPROFILE%\.gradle`; plain `flutter run` keeps using that path. `run_android_on_x.ps1` sets `GRADLE_USER_HOME=X:\gradle-home`. **Fix:** `-d emulator-5554` on that script caused `Target file "emulator-5554" not found` (PowerShell/flutter shim); use `-DeviceId emulator-5554` and pass `--device-id=…` internally; `patch_webcrypto_16k.ps1` early-exit uses `return` instead of `exit 0`.

## 2026-03-31 (evening) — Android GIF from localhost media URLs
- **Bug:** GIFs worked on web but showed broken image on Android emulator; server returned `mediaUrl` with `http://localhost:3000/media/...`, which the emulator resolves to itself (`connection refused`).
- **Fix:** `ApiService.fetchMediaBytes` rewrites loopback own-server `/media/*` URLs to match `AppConfig.baseUrl` host (e.g. `10.0.2.2:3000`) before `GET` (same pattern as already documented for authenticated media fetch).
- **Follow-up:** Removed temporary debug instrumentation (`agent_debug_log*.dart`, `[GIF-DBG]` prints) after user confirmed fix.

## 2026-03-31 — Android whole-app overscroll stretch
- **Issue:** On Android, dragging past scroll edges stretched/warped the entire UI (every screen), so layout looked like it was pulled apart vertically.
- **Cause:** Default Material 3 `StretchingOverscrollIndicator` via `MaterialScrollBehavior`.
- **Fix:** `MaterialApp.scrollBehavior` → `AppScrollBehavior` in `theme/app_scroll_behavior.dart` (`buildOverscrollIndicator` returns `child` only). Wired in `main.dart`.
