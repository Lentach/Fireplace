# Composer keyboard/focus/viewport — audit + targeted fixes (0.0.63)

**Date:** 2026-06-24

## What was done
Audited the chat composer keyboard/focus/viewport subsystem (the most band-aided area), then
implemented the recommended targeted fixes on branch `review/frontend-prod-readiness`. Report-first
audit doc + four code fixes (A2, B, C) + A1 observability. **No change to the E2E send path.**

**Audit:** `docs/review/composer-keyboard-audit.md` — per-symptom root cause, FIXABLE-vs-platform-limit
verdicts (incl. re-litigating the §9 "iOS send bounce = OS limit, do not iterate" call), remediation
plan, test-gaps, true-platform-limits list. Every claim source-verified with file:line.

**Fixes (recommended order C → B → A2 → A1):**
- **C (send-button bounce = focus-steal, not OS limit):** focus-guard hit-test now accepts a hit in
  EITHER raw `clientX/Y` space OR that point shifted by `visualViewport.offset*` (iOS offsets the
  visual viewport while the keyboard is up, so a touch's coords could miss the Flutter layout-space
  rect → `preventDefault` silently skipped → blur → bounce). Extracted pure VM-testable
  `focusGuardPointHitsAnyRect` into `utils/focus_guard_geometry.dart`.
- **B (laggy dark gap on keyboard hide):** `ChatComposerViewport`'s 450ms inset-collapse debounce now
  defers ONLY when `composerKeyboardCollapseGuard` is true (armed by the composer on
  send/edit/staged-send/action-toggle, 600ms auto-clear). A genuine user dismiss collapses the inset
  **immediately** — no gap. The debounce still masks the send-bounce flash, so flash AND lag solved
  together (constraint honored; banned global scroll-lock NOT reintroduced).
- **A2 (portrait overlay false-fires in portrait):** `shouldShowRotateOverlay` gains a
  `keyboardVisible` guard; `PortraitLockShell` passes `mq.viewInsets.bottom > 0`. A keyboard that
  transiently flips `MediaQuery.orientation` to landscape no longer triggers the rotate overlay.
- **A1 (Android white void — investigation-gated):** did NOT blind-change the `interactive-widget`
  meta. Widened the diag overlay to all web (`ComposerDiagnosticsOverlay.isAvailable = kIsWeb`) and
  added `innerHeight`/`screen.orientation` to the probe, so the next Android device session can name
  the mechanism (Flutter-web repaint #179208/#178431/#50382 vs stale composite).
