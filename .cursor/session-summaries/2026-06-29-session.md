# Chat entry split-screen lag fix

**Date:** 2026-06-29

## What was done
- Confirmed planning-with-files workflow: use persistent planning for multi-step/debug/deploy-sensitive work; skip for simple questions.
- Investigated screenshot-reported mobile chat-entry lag where the conversations tab and chat room were visible at the same time.
- Recorded screenshot observations before fixing: old `MainShell`/conversations route was visible on the left, new `ChatDetailScreen` route was partially slid in from the right, and the bottom nav bled through.
- Root cause: mobile chat-entry paths used `MaterialPageRoute`; its iOS-style horizontal transition exposes the previous route during entry, and a slow/janky mobile-web frame can visibly freeze that half-transition.
- Added `instantOpaqueRoute()` and switched chat-entry paths to opaque zero-duration routes so the previous tab is never exposed during chat entry.
- Bumped frontend version to `0.0.76`.
- Updated frontend memory and graph.
