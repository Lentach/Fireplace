## What was done

Owner report against live 0.2.3 (four nits, questions asked and answered up front):

1. **Square video bubbles** ("3 of 4 iPhone-PWA sends grey squares, receivers square too but playable; Android sends fine"). Diagnosis: grey square = `MediaPreviewFrame.legacyHeight` fallback = the E2E envelope carried no `mediaWidth/Height` = the composer's `probeVideoPreview` answered without geometry. **Two independent causes found, both fixed:**
   - `utils/video_probe_web.dart` read `videoWidth/videoHeight` at `loadedmetadata`, where WebKit still reports **0** for some QuickTime camera recordings (dimensions arrive on `resize`/`loadeddata`). The probe now waits ≤3 s (`_awaitGeometry`) when they are 0, and the blob is labelled by extension (`videoMimeForFilename`: `.mov` → `video/quicktime`) instead of a blanket `video/mp4`. **⚠️ NOT device-verified on iOS — no iOS device on the dev PC. Owner must test a camera recording from the iPhone PWA.**
   - **The video RETRY branch of `retryFailedMessage` dropped geometry + ThumbHash** (`messaging_provider.send.dart:1154`) — the image branch carried them, video did not. A clip whose first send failed (flaky phone link) and was retried reached the peer as a 220 px legacy square with a BLANK poster while the sender's optimistic bubble looked right; the sender's own persisted copy lost it on the ack merge too. Found by the browser smoke (my first send failed because the receiver had no key bundle yet, the retry produced exactly the owner's white square). Regression `messaging_provider_media_send_test.dart: a RETRY after the upload succeeded still carries geometry…` — red on the old code, green now.
   - Not built (owner call needed): receiver-side self-heal — persisting the real aspect ratio learned at first playback so pre-fix square bubbles fix themselves. Messages already sent without geometry stay square.
2. **Inline playback (Telegram model, owner picked "Telegram-exact")**: the 0.2.x "tap → fullscreen only" was deliberate but misdescribed Telegram, which autoplays muted inline and opens fullscreen on tap continuing from the same position. Now: `VideoMessageContent` is stateful; with `SettingsProvider.autoplayVideos` on (default TRUE, prefs `autoplay_videos`, new Settings → Preferences row `settings-autoplay-videos-row` with a Switch), an uploaded+decrypted row ≥60% on screen asks `InlineVideoArbiter` (new, single app-wide slot, newest wins, loser disposes — **mandatory because every session is a decrypted ≤20 MB blob in RAM**) and plays muted + looping cover-fit inside the same poster frame; remaining-time pill at 1 Hz via a `ValueNotifier`; speaker toggle `video_inline_mute_toggle` (per-bubble RAM state); tap → pause → `showVideoFullscreen(startAt:)` (plays with sound) → returns last position → bubble seeks there and resumes. Release below 30% visible, on revoke, dispose, settings flip, app pause. `rotationAwareAspectRatio` moved to `video_playback_session.dart` and shared.
   - **Second defect found live:** the receiver's bubble mounts with the plaintext `mediaUrl` column but no `mediaKey` until the Signal pass reaches it; the first load failed the decrypt, fell back silently, and nothing ever re-evaluated (no scroll). `_hasUploadedBlob` now also requires key+iv and `didUpdateWidget` re-evaluates when they land. Regression in `video_message_content_test.dart` (red → green).
3. **Fullscreen seek bar**: `Positioned(bottom:0)` + `SafeArea` + 12 px put the thumb inside Android's gesture-nav zone (SafeArea reports 0 in the Chrome PWA), so drags fired swipe-up-home. Now 64 px clearance; measured live at ~80 px from the bottom edge.
4. **Android camera door was photo-only**: `image/*` + `capture` is the still camera on Android Chrome; `video/*` + `capture` is the camcorder; there is no single input for both (iOS ignores `capture` and shows "Take Photo or Video", which is why iOS could). Added a 4th door **Nagraj wideo** (`attachment-door-record-video`, `video/*` + `capture=environment`). ARB: `attachmentOptionRecordVideo`, `videoUnmute`, `videoMute`, `settingsAutoplayVideos(+Subtitle)`.
