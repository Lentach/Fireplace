## Addendum — newline trailing control: IME flicker + long-press layout glitch

### Accomplished

- **Keyboard flicker** on trailing newline tap: `_insertNewline`, `_send`, and reply-bar focus no longer call `FocusNode.requestFocus()` when the composer **already has focus** (redundant `requestFocus` was toggling the IME). Trailing mic/newline column is wrapped in **`Focus(canRequestFocus: false, skipTraversal: true, descendantsAreFocusable: false)`** so those controls do not participate in focus traversal beside the multiline `TextField`.
- **Huge empty composer on long-press**: removed Material **`Tooltip`** from the newline control (long-press tooltip overlay conflicted with keyboard/scaffold); **`Semantics(button: true, label: chatComposerNewlineTooltip)`** keeps TalkBack/VoiceOver text from ARB.
- Ran `flutter test` (all passed), `flutter analyze` (same pre-existing web issues; no new issues in touched files), `graphify update .`.

## Addendum — IME send dismisses keyboard; composer height; trailing focus

### Accomplished

- **Keyboard after IME Send:** `TextField` **`onEditingComplete: () {}`** so Flutter’s default (unfocus on “Send”) does not close the IME while the focus node can still report focused in the same turn (avoids skipping a no-op `requestFocus` guard).
- **Async focus loss:** `_send` and `_insertNewline` schedule **post-frame** `requestFocus` only when **`!hasFocus`** after the platform settles.
- **Runaway composer height:** `ConstrainedBox` around the field with **text-scaled** max height (clamped 120–400) in addition to `maxLines: 6`.
- **Trailing newline / IME:** `InkWell` **`NoSplash.splashFactory`** + transparent splash/highlight; outer **`ExcludeFocus`** instead of `Focus(..., descendantsAreFocusable: false)` for the mic/newline stack.
- `flutter test`: **115** passed; `graphify update .`; `CLAUDE.md` composer bullet updated.
