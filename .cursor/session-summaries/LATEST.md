# Latest session summary

**Date:** 2026-06-07

**Topic:** Fixed voice (and all) media **playback failing on web**. Record+send worked everywhere; playback failed on every device for both own and received messages ("Nie udało się wczytać dźwięku" snackbar). Root cause: `ApiService._effectiveMediaUrl` had `if (kIsWeb) return url;`, so web never rewrote the stored `localhost` media host (`MEDIA_BASE_URL` default `http://localhost:3000`) to the real backend — native always rewrote, masking it. On any non-backend device, `localhost` = that device → fetch fails. Extracted a pure `rewriteLoopbackMediaUrl(url, baseUrl)` applied on **all platforms** (removed the web gate; adopts baseUrl authority fully via `port: b.port` so https same-origin loses the stray `:3000`). Before fixing, **empirically disproved** the typeless-blob/MIME hypothesis in real Chrome via Playwright (generated webm/opus + mp4/aac with MediaRecorder, both typed & typeless blobs play). Added regression test (note: `kIsWeb` is false under `flutter test`, so the web branch was invisible to the VM suite). v0.0.33. `flutter analyze` clean, full suite **282** green. **Pending user device confirmation** (no mic on this PC to reproduce web recording locally).
