# MessagingProvider decomposition (part-files + one leaf service)

**Date:** 2026-06-06

## What was done

Cut the 3009-line `messaging_provider.dart` god-file into a thin core + five
`extension`-wrapped part-files + one extracted leaf service, with **public API and
runtime behavior unchanged** (the spec's "behaviorally equivalent" guarantee).
Implemented the approved plan `docs/superpowers/plans/2026-06-06-messaging-provider-decomposition.md`
task-by-task, one reviewable commit per section, `flutter analyze` + full suite green
after every move.

- **Task 1** — extracted `IncomingMessageSoundService` (real class, own unit test, +3 tests). The provider holds `final _incomingSound = IncomingMessageSoundService();` and delegates.
- **Task 2** — scaffolded the five empty public `extension … on MessagingProvider` part-files + `part` directives.
- **Task 3** — hoisted the five bare-referenced statics (`_e2eFlowLog`, `_pageSize`, `_deliveryStatusRank`, `_kDecryptionFailedLabel`, `_kEncryptedPlaceholderLabel`) to **library-private top-level** (extensions can't see a class's statics). `_tempIdSeq` stays a class static (always written `MessagingProvider._tempIdSeq`).
- **Tasks 4–8** — moved `history` (19), `events` (19), `send` (20), `decrypt` (16), `actions` (8) methods verbatim into their extensions, then removed the orphaned section-divider comments the cuts left in core.

**Deviation from the literal plan (documented):** the spec assumed bodies move
verbatim with zero analyzer fallout, but `notifyListeners()` is `@protected` /
`@visibleForTesting` on `ChangeNotifier` and the analyzer flags it when called from an
`extension` (not a subclass body). To preserve the spec's central **verbatim-bodies**
guarantee, each part-file carries a file-scoped
`// ignore_for_file: invalid_use_of_protected_member, invalid_use_of_visible_for_testing_member`
(the standard idiom for extensions on a `ChangeNotifier`) rather than rewriting every
`notifyListeners()` call. Also: `IncomingMessageSoundService.setEnabledForTest` is **not**
`@visibleForTesting` (the provider's own test hook calls it from lib code, which would
otherwise flag).

Core shrank **3009 → 469 lines**. Parts: history 513, events 299, send 1106, decrypt 590,
actions 72; service 46.
