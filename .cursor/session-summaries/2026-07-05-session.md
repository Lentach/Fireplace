# Emote/emoji message rendering — Telegram parity fixes (0.0.87)

**Date:** 2026-07-05

## What was done
Fixed four emoji/emote rendering issues on the Flutter web/PWA chat bubble, matching Telegram. Branch `fix/emote-message-layout`, version bumped `0.0.86 → 0.0.87`.

- **P1 (single emote shoved to center) + P2 (indicators missing on iOS Safari):** the emoji-only branch in `chat_message_bubble.dart` laid the emote and `MessageMetadataRow` **side-by-side in a `Wrap`** (`spacing:6`), so a lone emote + inline time run read as center-shifted, and the inline run collapsed on iOS WebKit (Apple emoji glyph advance differs from Noto → the metadata run beside the wide jumbo glyph dropped/mismeasured). Replaced the `Wrap` with a side-aligned `Column` (`crossAxisAlignment` = end/start by `isMine`) → emote flush to its side, metadata stacked directly **under** it (4px gap). Same `Column`+side-alignment the multi-line text/media-caption paths already use reliably on iOS. Indicators now under the emote for ALL counts (1/2/3+).
- **P3 (jumbo size tuning):** `jumbo_emoji.dart` tiers retuned `1→82, 2→78, 3→64, 4→52, 5+→44` (was `1→84, 2→84, ...`). Single −2, 2-emote now distinctly smaller than single, steep late tiers kept so multi-emoji rows don't overflow.
- **P4 (inline emoji too small in mixed text):** added `buildInlineEmojiSpans()` + `isEmojiGrapheme()` + `kInlineEmojiFontSize = 18` in `jumbo_emoji.dart`. Mixed (non-jumbo) text now splits into runs; emoji runs render at 18px while text/URLs stay 14px. Kept inline in the single RichText (no jumbo). Applied in `text_message_content.dart` (both pre-URL and trailing segments) and mirrored in the context-menu replica.
- **Context-menu replica** (`message_context_menu_bubble_highlight.dart`): mirrors the above — jumbo auto-follows the tier table, mixed text uses `Text.rich` with split spans (base 15px, emoji 18px), and emoji-only now stacks the metadata below (forced `!isEmojiOnly` on `useInlineTime`).

### Follow-up (same session, device-QA feedback)
- **Reply-to-emote bubble stretch (Image 1):** replying to an emote produced a bubble stretched to the full max width with the small emote quote adrift in empty space. Root cause (measured, platform-independent): the non-inline metadata branches wrapped `standardTimeWidget` in an `Align`, and `Align` greedily fills its bounded width → forced the bubble surface to `maxBubbleWidth − leftPad` (283.5px) regardless of content. Removed both `Align` wrappers in `chat_message_bubble.dart`; the parent `Column`'s `crossAxisAlignment` already side-aligns, so the bubble now shrink-wraps (measured 283.5→127px for a one-emote quote). Affects all non-inline bubbles (replies + multi-line text) → they now hug content, Telegram-style.
- **Persisted iOS "no indicators for sent emotes" (Image 2) — REAL root cause:** NOT a WebKit `Wrap` drop (earlier theory). It is theme + bubbleless: `messageBubbleMetaColor(isMine:true, teal/blue)` returns white (α0.9) — correct on the colored sent bubble, invisible on the bubbleless emote's light chat background (user confirmed dark theme showed it fine). Fix scoped to the emote branch only: metadata now uses the received-side `messageBubbleMetaColor(isMine:false)` (background-readable in both themes) + new `MessageMetadataRow.onChatSurface` flag that renders the delivery tick with readable colors (sent = timeColor, read = theme primary) instead of the pale on-bubble palette. `messageBubbleMetaColor` and normal/media callers untouched.
