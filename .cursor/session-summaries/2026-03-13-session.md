# Session summary — 2026-03-13

## Accomplished
- **Send when recipient offline**: Fixed unreliable send/retry when user A sends to B while B is offline. Root cause: E2E session fails when B has no key bundle in DB (B uploads keys on login); retry sometimes failed due to stale pre-key fetch state or timing (A retries before B’s keys are saved).
- Removed debug instrumentation (agent log regions and HTTP ingest) added for the previous debug session.
- Implemented:
  1. **Clear pending pre-key on failure**: In `_encryptAndSend` catch block, call `_pendingPreKeyFetches.remove(recipientId)` so the next send/retry does a fresh `fetchPreKeyBundle` instead of reusing a failed completer.
  2. **Delayed auto-retry**: When failure is key-bundle or timeout (`_isKeyBundleOrTimeoutError`), schedule a single delayed retry after 4 seconds (`_scheduleDelayedRetry`). When B logs in and uploads keys, the message can send without the user tapping Retry.
  3. **Retry in place**: `_retrySendInPlace(tempId)` reuses the same message (same `tempId`), sets status to sending, and calls `_encryptAndSend` again so `messageSent` replaces the optimistic message as usual.
  4. **Cancel delayed retry**: Manual Retry cancels the timer for that `tempId` (`_cancelDelayedRetry(tempId)` in `retryFailedMessage`). Connect/logout clears any pending delayed retry (`_cancelDelayedRetryIfAny()` in `connect()`).
