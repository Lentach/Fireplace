# Emote composer: native-emoji verdict, send-scroll, panel-swap animation (0.0.88)

**Date:** 2026-07-06

## What was done
Three reported emote/composer issues on branch `fix/emote-composer-scroll-anim`; version `0.0.87 → 0.0.88`.

- **A (native per-platform emoji) — DROPPED as impossible, per user's "if impossible drop it".** There is no bundled emoji font in the app: picker/composer/messages use plain text styles and glyphs come from the Flutter web engine. CanvasKit/Skwasm (Flutter 3.41; HTML renderer removed in 3.29) rasterizes all text from its own loaded font bytes on a canvas — browsers expose no system-font bytes, so emoji are always the engine-downloaded Noto Color Emoji on every OS. Open upstream requests: flutter#166769, flutter#157918. Only "workarounds" are bundling Apple's proprietary ~180MB font (illegal) or DOM platform-views for every emoji surface (massive rewrite). User informed; idea dropped.
- **B (emote send doesn't scroll to newest):** root cause — `chat_detail_screen.dart` `_onNewMessages` scrolled only when `_wasNearBottom && !_userHasScrolledChat`; text sends *appeared* to scroll because focusing the composer opens the keyboard and `didChangeMetrics` scrolls on keyboard-open. The emote panel opens without the keyboard → no scroll. Fix: new pure helper `utils/chat_auto_scroll.dart` (`shouldAutoScrollOnNewMessages`) — own sends ALWAYS scroll (text/emote/media alike); peer messages keep near-bottom-only + badge behavior.
- **C (keyboard→emote-panel switch: panel drops from the top):** root cause — the composer block (input row + 320px panel) is `Positioned(bottom: _keyboardInset)` in `ChatComposerViewport`; on the switch the panel mounts while the inset is still ~300px, hovering the block near the top, then rides the collapsing inset down. Fix: new global `composerBottomPanelPinned` `ValueNotifier` (in `composer_keyboard_signals.dart`, same pattern as the collapse guard). `ChatInputBar` syncs it via a single mutation point `_setEmojiPickerVisible()` (all 6 `_showEmojiPicker` assignment sites + deferred reset in `dispose` — sync notify there would hit the ancestor viewport's setState during tree finalization). While pinned, the viewport anchors the composer at `bottom: 0` and derives list padding from the same effective inset, so the panel occupies the keyboard's space from the first frame and the dismissing keyboard just reveals it (native-style swap; no top-origin drop, no gap).
