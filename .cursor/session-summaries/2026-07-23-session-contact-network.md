# Contact Network — node-map presentation for the Contacts tab

**Date:** 2026-07-23

## What was done
1. **Built `ContactNetworkView`** (`frontend/lib/widgets/contact_network_view.dart`, new): the Contacts tab renders the existing contact set as a network map — current user is a circular "local node" (instrument reticle: outer ring, N/E/S/W ticks, accent inner ring), each real contact a clipped-corner terminal (reinforced corners, inner inset frame, symmetric 5x5 identicon from id hash, initials, real username caption). Strictly a re-render of `FriendsProvider.friends`: no fake nodes, no contact-to-contact edges, no invented status. Doubled traces mark real existing conversations; the `NODES NN` caption uses the real count.
2. **Visual language** (authored in-session after the first "generic" iteration was rejected): sparse `+` tick field with radial falloff from the local node (no full-bleed grid), dashed elliptical orbit guides, PCB-style dogleg traces (one 45° bend, port stub + pads at both ends — never vanishing under a node), screen-fixed corner brackets, one-shot entrance pulse with fading tail along the bent path. The one-contact hero state is a deliberate diagonal composition with an accent trace and a short orbital target arc around the contact.
3. **Layout engine** (kept from the aborted worker session, then upgraded): pure deterministic `ContactNetworkLayout` measured from live viewport + `TextScaler` (labels measured with `TextPainter`, ceil+1 to prevent glyph clipping at accessibility scales). Elliptical rings (independent x/y radii) fill portrait/landscape space; a lone ring widens to 0.72 of the max extents. Collision resolution seeds `occupied` with the local node rect; candidate order is ring offsets → deterministic full-bounds sweep (coarse stride — broadens coverage but can miss narrow gaps) → least-overlap fallback for exhausted/impossible layouts. Pairwise no-overlap is contract-tested for fitted, long-label, and dense-interactive layouts.
4. **Interactions:** tap → highlight pulse → existing `_openContactCard` (UserCardScreen, Message/mute/remove all unchanged); long-press drag pins a node (per-user SharedPreferences key `contact_network_layout_v1_<uid>`, normalized coords treated as *hints* — clamped + de-overlapped every build); Reset layout clears pins; header trailing IconButton toggles to the classic list (kept verbatim as accessibility/lookup fallback); dense networks get `InteractiveViewer` pan/zoom opening centered on the local node.
5. **Accessibility as core invariant:** every node is a semantic *boundary* button labeled with the username (found and fixed a merge bug where all labels collapsed into the map container node), traversal order = the natural sorted order (OrdinalSortKey), keyboard Tab/Enter works, keyboard focus pans the interactive map to fully reveal the focused node, 48dp hit-target floor, reduce-motion → static map + synchronous tap routing.
6. **`MainTabScreenHeader` fix** (shared widget): title is now truly centered via a Stack (full-width `IgnorePointer` title behind `Positioned` side controls). The old `Expanded` Row shifted the title with asymmetric controls — visible on Chats (leading avatar) and blocking the new trailing toggle. First Stack attempt with non-positioned `Align` painted the trailing icon over the title; explicit `Positioned(left/right:0, top:0, bottom:0)` is the working shape.
7. **Wiring** (`contacts_screen.dart` → StatefulWidget): network is the default presentation; `conversationContactIds` derived from `ConversationsProvider.conversations` via `getOtherUser`; `pendingOpenConversationId` consumption, `instantOpaqueRoute` chat entry, natural sort all untouched. New ARB keys (en+pl; pl is the template and carries placeholder metadata): `contactNetworkLocalNode/YouLocalNode/Semantic/Nodes/Reset/DragHint/ShowList/ShowMap`.
