- **Mechanism (proven by execution).** `SharedPreferences.reload()` reads the store, AWAITS, then clears its in-memory cache and refills it from the snapshot it took — a write landing in that window survives in the store but is **dropped from the cache**, so `getString` returns null for a record that is physically present. Raw-plugin proof: `READ CACHE: null / REAL STORE: PLAINTEXT`; at volume 3/89 lost from cache, **0/89 from the store**. A missed plaintext record re-decrypts a consumed ratchet key → `DuplicateMessage` → permanent `[Decryption failed]` while the only copy sits on disk. Matches the owner's log exactly (`kind: duplicate`, `persist: false`, 42 ids).
- **Causation is circumstantial, NOT proven** — the harness forces the cache drop; the device needs a real reload racing a real write. It is the only surviving mechanism. **The deploy is the falsifiable test:** if the 42 render again, confirmed; if they stay failed, the theory is wrong and the records were never written. Deploying master+fix **restores all 0.0.136 machinery the rollback removed**.
- **Why a pre-existing hazard started firing:** web-only (`_reloadPrefsForCrossContext` is `kIsWeb`-gated), 10 reload sites at 0.0.134 → **18** now, plus `sweepDestroyablePlaintext`/`drainPurgeBacklog`/`reconcileStoredPlaintext`/`_startPlaintextSweepTimer`, **all four absent at `a00ab0f`**: a 60s timer and a launch drain/sweep/reconcile chain reloading while inbound decrypts persist.
- **Fix:** record readers read the backing store, **web-gated** (`_authoritativeSnapshot`). A lock cannot work — `signal_stores.dart` reloads the same singleton during decrypt. Off web nothing reloads, so the cache is correct and free; unconditional `getAll()` would serialise the whole prefs map per decrypted message. **LRU prune deliberately still counts via the cache** — it undercounts, suppressing eviction, and eviction calls `markRetired` (permanent).
- **Second, independent data-loss bug fixed:** `saveDecryptedContent` built `{...data}` unconditionally, so the terminal-failure write replaced real plaintext and hydration (`decrypt.dart:411`) skipped it forever. Fails-before deterministically. Explains the 27 `badMac` rows (sender 60), **not** the 42.
